# Задача 16. Сортировка по модулю

## Обозначения

`n` — число элементов массива, `2 ≤ n ≤ 99999`. Оценки даны для допустимого входа. Операции с `int` и `long` считаются постоянными по времени. O обозначает верхнюю оценку, Θ — точный порядок роста. Оценка описывает зависимость от n, несмотря на заданный предел размера.

## Идея решения

Элементы копируются в Integer[]. Arrays.sort с компаратором сравнивает модули; при равных модулях сравниваются сами числа. Результат переносится в исходный int[].

## Временная сложность метода

Создание и заполнение Integer[] занимает Θ(n). Одно сравнение модулей занимает Θ(1), поскольку используются числа фиксированной разрядности. Сортировка объектов занимает O(n log n) в худшем случае, обратное копирование — Θ(n). Итого O(n + n log n + n) = O(n log n). Для адаптивной сортировки объектов на уже упорядоченных данных возможен лучший случай Θ(n).

## Пространственная сложность

Массив Integer[], объекты-обёртки и вспомогательная память сортировки суммарно требуют O(n). Сам массив копии уже требует Θ(n), поэтому дополнительная память всей реализации — Θ(n). Модуль вычисляется после преобразования в long, чтобы обработать Integer.MIN_VALUE.

Исходный массив занимает Θ(n). Общая память программы с учётом входного массива — Θ(n).

## Ввод и вывод

Считывание n чисел требует Θ(n) времени при фиксированной разрядности int. Вывод массива содержит не более n чисел и занимает O(n). Поэтому ввод и вывод не увеличивают приведённую основную оценку времени; для линейного метода полное время также Θ(n).

## Ручные тесты

Индексы начинаются с нуля. Перед массивом при запуске main вводится его длина; дополнительные параметры передаются в порядке, установленном кодом main.

```text
[-3, 1, -1, 2] → [-1, 1, 2, -3]
[0, -2, 2] → [0, -2, 2]
[-2147483648, 2147483647] → [2147483647, -2147483648]
```
