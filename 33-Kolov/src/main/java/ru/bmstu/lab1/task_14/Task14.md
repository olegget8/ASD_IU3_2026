# Задача 27. Сумма квадратов

## Обозначения

`n` — число элементов массива, `2 ≤ n ≤ 99999`. Оценки даны для допустимого входа. Операции с `int` и `long` считаются постоянными по времени. O обозначает верхнюю оценку, Θ — точный порядок роста. Оценка описывает зависимость от n, несмотря на заданный предел размера.

## Идея решения

Квадрат каждого элемента вычисляется в long, затем добавляется к сумме BigInteger. Приведение к long выполняется до умножения. BigInteger нужен, поскольку общая сумма может не поместиться в long.

## Временная сложность метода

Цикл выполняет n итераций. Для заданных ограничений |arr[i]| ≤ 2³¹ и n ≤ 99999 сумма не превышает 99999·2⁶² < 2⁷⁹, то есть занимает не более 79 бит. Размер операндов BigInteger ограничен константой; одно сложение имеет ограниченную стоимость. Поэтому в рамках задачи T(n) = Θ(n). Если формально снять ограничение на n, сумма требует O(log n) бит, а последовательные сложения BigInteger дают верхнюю оценку O(n log n) в битовой модели.

## Пространственная сложность

При заданных ограничениях одновременно нужны только сумма ограниченного размера, очередной квадрат и временный результат сложения: Θ(1) дополнительной живой памяти. BigInteger неизменяемый: за весь цикл создаётся O(n) временных объектов, но это не означает O(n) одновременно необходимой памяти. Без ограничения на n объём накопителя составил бы O(log n) бит.

Исходный массив занимает Θ(n). Общая память программы с учётом входного массива — Θ(n).

## Ввод и вывод

Считывание n чисел требует Θ(n) времени при фиксированной разрядности int. Вывод результата при заданных ограничениях занимает Θ(1). Поэтому ввод и вывод не увеличивают приведённую основную оценку времени; для линейного метода полное время также Θ(n).
