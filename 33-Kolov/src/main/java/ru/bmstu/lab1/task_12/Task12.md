# Задача 17. Сортировка по сумме цифр

## Обозначения

`n` — число элементов массива, `2 ≤ n ≤ 99999`. Оценки даны для допустимого входа. Операции с `int` и `long` считаются постоянными по времени. O обозначает верхнюю оценку, Θ — точный порядок роста. Оценка описывает зависимость от n, несмотря на заданный предел размера.

## Идея решения

Неотрицательные числа копируются в Integer[] и сортируются устойчивой сортировкой с компаратором по сумме цифр. При равных суммах компаратор возвращает 0, поэтому сохраняется исходный порядок.

## Временная сложность метода

Пусть d — максимальное число десятичных цифр. digitSum выполняет не более d шагов, сравнение двух элементов — O(d). При вычислении сумм внутри компаратора сортировка требует O(d·n log n) времени в худшем случае. Проверка элементов и копирование требуют O(n). Для Java int число цифр не превышает 10, поэтому d — константа и итог — O(n log n). При уже упорядоченных данных адаптивная сортировка может работать за Θ(n) для фиксированного int.

## Пространственная сложность

Integer[], обёртки и вспомогательная память сортировки требуют Θ(n) дополнительной памяти. digitSum использует Θ(1) памяти; суммы цифр в этой реализации заранее не кешируются.

Исходный массив занимает Θ(n). Общая память программы с учётом входного массива — Θ(n).

## Ввод и вывод

Считывание n чисел требует Θ(n) времени при фиксированной разрядности int. Вывод массива содержит не более n чисел и занимает O(n). Поэтому ввод и вывод не увеличивают приведённую основную оценку времени; для линейного метода полное время также Θ(n).

## Ручные тесты

Индексы начинаются с нуля. Перед массивом при запуске main вводится его длина; дополнительные параметры передаются в порядке, установленном кодом main.

```text
[12, 20, 3, 11] → [20, 11, 12, 3]
[0, 10, 1] → [0, 10, 1]
[21, 12, 3] → [21, 12, 3]
```
